1整體分層

3認證與權限

系統有兩套互不相通的登入：

  1. 後台：AuthController::createToken 以 username + 密碼驗證，檢查 is_active，更新 last_login_at，回傳 Sanctum token。前端存入 localStorage.api_token，http.js 在每個請求加上 Authorization: Bearer；收到 401 時清除 token 並導回 /admin/login。
  2. 前台：Frontend\Auth\LoginController 用 Auth::attempt 建立 session；登入後不是 customer 角色就立即登出並顯示「此帳號無法使用前台登入。」註冊時自動指派 customer。

權限檢查的三層

層位置做法
選單顯示layout/components/Sidebar.vue依 route meta.permission 以 can() 過濾；super-admin 全部可見
路由守衛router/index.js · beforeEach無 token 導向登入；缺權限導回 /admin/dashboard
API各控制器 $this->authorize('...')搭配 Gate::before 讓 super-admin 通過所有檢查。所有後台資源控制器（含分類、產品圖片、用量、專案設定、詢價訂單）都有呼叫 authorize；富文字上傳改以 canAny 檢查

4API 格式與錯誤處理

控制器使用 App\Traits\ApiResponse：successResponse($data, $message = 'Operation successful', $code = 200) 與 errorResponse($message, $errorCode, $httpCode = 400, $errors = [])。例外在 bootstrap/app.php 統一轉成同樣格式（僅限 api/* 或要求 JSON 的請求）：

例外HTTPerror_code前端顯示（http.js）
ValidationException422VALIDATION_ERROR「資料驗證失敗，請檢查輸入欄位」；欄位錯誤在 errors
ModelNotFoundException404RESOURCE_NOT_FOUND「查無此資料」
AuthenticationException401UNAUTHENTICATED不顯示訊息，清除 token 並導回登入頁
其他 Throwable500SERVER_ERROR「系統內部錯誤…」；debug 模式時 message 為原始錯誤

前端先用 error_code 查 resources/js/constants/errors.ts，查不到才用後端 message，最後退回「系統發生未預期的錯誤」。http.js 的請求攔截器也會啟動全域 loading 遮罩，除非請求設定 globalLoading: false。

5多語系

  • 語系清單：languages 資料表（Language::getActive()、getDefault()）。seeder 建立 en（預設）與 zh-TW。
  • 內容欄位：Model 使用 spatie/laravel-translatable 的 HasTranslations，$translatable 欄位以 JSON 儲存，鍵為語系碼（zh-TW、en）。API 驗證時 name.zh-TW 為必填。
  • 前台連結：lroute($name)（app/Helpers/routes.php）在非預設語系時改用 $name.localized 路由並帶入 locale。
  • 後台介面文字：admin/main.js 啟動時呼叫 /api/translations/{locale}?scope=admin，把 lang/{locale}/admin.php 攤平成 key 對照表，提供全域 $t()；後端快取 3600 秒。

6產品、分類與圖片

分類樹

  • ProductCategory 以 parent_id 形成無限層級；children() 取直接子層。
  • 前台 ProductController::getCategoryIdsRecursive 遞迴收集分類與所有子孫 ID，分類頁列出其中所有產品（每頁 12 筆）。
  • 更新時拒絕把自己（INVALID_PARENT）或子孫（LOOP_RELATION）設為父層。
  • 刪除規則：系統分類（is_system，即「未分類」）回 403；仍有子分類回 422 HAS_CHILD_CATEGORIES；否則把其下產品移到預設分類後刪除，回傳 reassigned_products。

Slug 自動產生

  1. Observer creating/updating：有手動填 slug 就 Str::slug() 清理；名稱改變且未改 slug 時重新產生。
  2. SlugService::buildBaseSlug：先試 Str::slug(名稱)，中文結果為空時改用 overtrue/pinyin 轉拼音，仍為空則用 item- + md5 前 8 碼。名稱優先取 zh-TW，再取 en。
  3. ensureUnique：同專案內重複時加上 -1、-2…

圖片處理（ImageService，Intervention Image）

類型上傳上限輸出路徑
產品圖jpg/png/webp，每張 2MB，一次最多 10 張補白成正方形 JPG：main 1000、thumb 500、tiny 150 px，品質 80uploads/products/{size}/
輪播圖電腦版 5MB、手機版 2MB等比縮小至 1920 / 800 px 寬，品質 85uploads/banners/{pc|mobile}/
分類縮圖jpg/png/webp，2MB等比縮小至 600×600 內，品質 80uploads/categories/

資料庫存相對路徑，API Resource 以 asset('storage/' . $path) 轉成完整網址。

前台的「加入詢價車」、詢價車圖示與產品價格區塊目前以 @if(false) 隱藏；/inquiry 路由、InquiryController 與後台「詢價訂單」仍然存在，Alpine 的購物車 store 以 localStorage.inquiry_cart 保存。

8前台表單、郵件與驗證碼

  • 聯絡表單（ContactController::submit）：驗證姓名、Email、訊息（上限 2000 字）→ 驗證碼 → 以專案 SMTP 寄「網站聯絡表單通知」到 contact_email。寄信例外會被吞掉，使用者仍看到成功訊息。
  • 詢價單（InquiryController::store）：驗證碼 → 驗證欄位 → transaction 建立 orders 與 order_items（價格取自產品目前價格）→ 寄 InquirySubmittedMail。前台入口目前隱藏。
  • ProjectMailService：專案有 smtp_host 與 smtp_username 時建立該專案專屬 mailer（預設 port 587、tls），否則用 Laravel 預設 mailer。smtp_password 以 encrypted cast 儲存並列在 $hidden。
  • CaptchaService：依 captcha_provider（none / recaptcha / turnstile）向 Google 或 Cloudflare 的 siteverify 驗證。
  • 測試信：POST /api/projects/{id}/test-smtp，未設定 SMTP 或聯絡信箱時回 422。

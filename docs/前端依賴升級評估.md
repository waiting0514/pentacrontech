# 前端依賴升級評估（Vite 8 / Vue 生態）

評估日期：2026-11-09

## 1. 結論

- **目前不需要升級。** 所有套件都在各自大版本的最新版，沒有安全或相容性急迫性。
- Vue 本體（`vue ^3.5.27`）已是最新，無需處理。
- 若要升級，**只有 Vite 8 值得考慮**，且必須與 `laravel-vite-plugin` 3 一起升。
- Pinia 4、vue-router 5、concurrently 10、unplugin-vue-components 32 **建議維持現狀**，理由見第 3 節。

## 3. 各套件評估

### 3.1 Vite 7 → 8（成本：低～中）

**Node 需求：** `^20.19.0 || >=22.12.0`，與 Vite 7 相同。目前容器是 Node 24，符合。

**最大變動：** 打包器從 Rollup + esbuild 換成 **Rolldown + Oxc**。

**本專案受影響的項目（已檢查 `vite.config.js`）：**

| 項目 | 本專案狀況 | 影響 |
|---|---|---|
| `build.rollupOptions` / `manualChunks` | 未使用 | 無 |
| `esbuild` 選項 | 未使用 | 無 |
| `optimizeDeps.include` | 有使用 | 仍支援，預期無影響 |
| `server.watch.usePolling` 等 | 有使用 | 非打包器設定，預期無影響 |
| 預設瀏覽器目標提高 | Chrome/Edge 111、Firefox 114、Safari 16.4 | 若需支援更舊瀏覽器要確認 |
| CSS 壓縮改用 Lightning CSS | 預設 | 產出 CSS 可能略大或有細微差異，需目視檢查 |
| JS 壓縮改用 Oxc | 預設 | 需實際跑 build 並驗證功能 |
| CJS 預設匯入（interop）行為變更 | 可能影響 CJS 套件 | 重點檢查 Quill、`@vueup/vue-quill`、axios |

**風險點：**
- `@vueup/vue-quill`、`quill` 是 CJS/UMD 風格套件，最可能因 CJS interop 變更而出問題，富文字編輯器要重點測試。
- Element Plus 按需載入若使用 `unplugin-vue-components`，要確認外掛與 Vite 8 相容（目前 `vite.config.js` 與 `resources/` 內都沒有引用 `unplugin-*`，這兩個套件可能是未使用的依賴）。

### 3.2 laravel-vite-plugin 2 → 3（成本：低，須隨 Vite 8）

- v3 的 peer dependency 是 `vite ^8.0.0`，**不能與 Vite 7 搭配**，所以必須和 Vite 8 同時升。
- 官方說明有「upgrade guide」，實際升級前請先讀 https://github.com/laravel/vite-plugin/blob/main/UPGRADE.md（本次評估未取得完整內容，這是待確認項）。
- v3 新增字型優化相關功能（需要 `fontaine` peer，選用），不影響現有設定。
- 本專案 `vite.config.js` 只用 `input` 與 `refresh`，預期不需改設定。

### 3.3 Pinia 3 → 4（成本：中，不建議）

- v4 為 **ESM only**，且 `@vue/devtools-api` 升到 v8 並需另外安裝。
- peer 要求 `vue ^3.5.11`、`typescript >=5.6.0`（TypeScript 為選用，本專案是 JS）。
- 效益：目前沒有看到對本專案有實質幫助的新功能。
- 風險：需要回歸測試所有 `resources/js/admin/store/modules/` 下的 store。

### 3.4 vue-router 4 → 5（成本：低，但無必要）

- 官方說明：**只用 vue-router 4、沒用 `unplugin-vue-router` 的專案沒有破壞性變更**。
- peer 要求 `vue ^3.5.34`、`vite ^7.3.0 || ^8.0.0`；目前 vue 版本需確認 `>= 3.5.34`。
- 無明顯效益，維持 4 即可。若升級，驗證重點是 `resources/js/admin/router/index.js` 的權限守衛。

### 3.5 concurrently 9 → 10（不建議）

- v10 要求 **Node >= 22**。
- 只用於 `composer dev` 腳本，沒有升級必要。

### 3.6 unplugin-vue-components 31 → 32（不建議）

- v32 要求 Node >= 20.19.0，與 Vite 8 一致。
- 專案內沒有引用，先確認是否為閒置依賴；若是，可考慮移除而非升級。

## 4. 若決定升級 Vite 8：建議步驟

建議獨立開一個分支，**一次只做這一件事**，所有指令都在 Sail 容器內以 sail 使用者執行。

1. **建立基準**
   - `git switch -c chore/vite-8`
   - `./vendor/bin/sail npm run build`，記錄 `public/build` 的檔案大小與數量作為對照。
2. **升級套件**
   - `./vendor/bin/sail npm install vite@^8 laravel-vite-plugin@^3`
   - 其他套件（plugin-vue、tailwind）維持不動，已相容。
3. **建置與開發伺服器**
   - `./vendor/bin/sail npm run build`，確認沒有錯誤與棄用警告。
   - `./vendor/bin/sail npm run dev`，確認 HMR 運作（Docker 環境下注意 `usePolling` 與 `hmr.host`）。
4. **功能驗證（重點）**
   - 後台登入、側邊選單、權限守衛路由
   - 商品編輯：圖片上傳、**富文字編輯器（Quill）**、PDF 附件
   - 新聞、影片、Banner 管理
   - 前台頁面（Blade + `resources/js/app.js`）樣式是否正常
   - 瀏覽器 Console 無錯誤
5. **檢查產出**
   - 比較 `public/build` 大小與基準，確認沒有異常膨脹。
   - 檢查 Tailwind 樣式與 Element Plus 樣式是否完整。
6. **自動化測試**
   - `./vendor/bin/sail artisan test`
7. **提交**
   - 只提交 `package.json` 與 `package-lock.json`；部署流程需確認伺服器 Node 版本 >= 20.19。

## 5. 回滾方案

- 在升級前確保 `package.json` 與 `package-lock.json` 已提交。
- 問題無法快速解決時：`git checkout -- package.json package-lock.json`，再執行 `./vendor/bin/sail npm ci`。

## 7. 待確認事項

1. 閱讀 `laravel/vite-plugin` 的 UPGRADE.md，確認 v3 沒有額外破壞性變更。
2. 確認生產環境（`deploy/` 內的設定）使用的 Node 版本是否 >= 20.19。
3. 確認 `unplugin-auto-import`、`unplugin-vue-components` 是否為未使用依賴，可考慮移除。
4. 確認實際支援的瀏覽器範圍是否能接受 Vite 8 的新預設目標。

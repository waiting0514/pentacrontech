# 部署檢查表：已知問題修正（2026-10-01）

對應 commit：`fix: 修正系統架構說明列出的 14 項已知問題`。修正內容見 `docs/系統架構說明.html` 第 11 節。

## 影響摘要

| 項目 | 部署後的變化 |
|---|---|
| 專案設定 API 權限 | 非 super-admin 呼叫 `PUT/DELETE /api/projects/*`、`test-smtp`、`switch` 回 403（後台選單本來就看不到） |
| 驗證碼金鑰 | 改為加密儲存；API 只回傳「已設定」旗標；設定頁留空表示不修改 |
| 其他 API 權限 | 分類、產品圖片、用量、詢價訂單、上傳都檢查權限；editor 無法刪除產品分類 |
| 403 回應 | 權限不足回 403（`error_code: UNAUTHORIZED`），不再變 500；`abort()` 的狀態碼也會保留 |
| 維護模式 | 開啟後**整個前台**回 503，不只首頁（含登入／註冊頁，不含 `/admin` 與 API） |
| 前台登入／註冊 | GET 改為多語系路由（`/en/login`）；停用帳號無法登入 |
| `GET /api/test` | 已移除，外部監控若打這支會收到 404（健康檢查請用 `/up`） |
| 其他 | 用量統計不再 NaN、RAG 可搜中文、排程只註冊一次、專案判斷統一用第一個專案 |

## 部署前

- [ ] **備份資料庫。**
- [ ] 確認正式站 `APP_KEY` 與 `.env` 不會在這次更新中被更換（金鑰加密依賴它，換掉後金鑰無法解密）。
- [ ] 查看目前 `maintenance_mode` 是否為開啟：
  ```bash
  php artisan tinker --execute="echo \App\Models\Project::first()->maintenance_mode ? 'ON' : 'OFF';"
  ```
  若為 ON，部署後整個前台會顯示維護畫面，請確認是否預期。
- [ ] 確認沒有外部監控／排程在呼叫 `/api/test`。
- [ ] 若有 staging，先在 staging 完整跑一遍下方流程。

## 部署

migration 與新程式碼請**一起上線**（只上其中一邊，驗證碼驗證會暫時失敗或讀取金鑰時報錯）。

```bash
git pull
composer install --no-dev --optimize-autoloader
php artisan migrate --force        # 加密 recaptcha / turnstile secret key
npm ci && npm run build            # 後台 Vue 有修改，必須重新 build
php artisan route:clear            # 或 route:cache；登入／註冊改為多語系路由
php artisan config:cache && php artisan view:clear
```

### 補上 `order.view` 權限

**不要在正式站執行完整的 `RolesAndPermissionsSeeder`。** 它會建立 `admin@example.com`、`manager@example.com`（密碼 `password`），並把沒有角色的使用者全部指派為 editor。只新增這一個權限：

```bash
php artisan tinker --execute="\Spatie\Permission\Models\Permission::firstOrCreate(['name'=>'order.view']); \Spatie\Permission\Models\Role::findByName('manager')->givePermissionTo('order.view'); app(\Spatie\Permission\PermissionRegistrar::class)->forgetCachedPermissions();"
```

## 部署後驗證

- [ ] super-admin 登入後台，「系統設定」的驗證碼 Secret Key 欄位顯示「已設定（留空不修改）」。
- [ ] 前台送出一次聯絡表單，驗證碼與寄信正常（確認金鑰解密成功）。
- [ ] editor 帳號呼叫 `PUT /api/projects/{id}` 回 403；editor 在後台刪除產品分類被拒絕。
- [ ] manager 帳號看得到「詢價訂單」；editor 看不到。
- [ ] 後台總覽重新整理後，super-admin 仍顯示正確的預算與用量；「用量監控」不再出現 NT$NaN。
- [ ] 前台 `/login`、`/en/login` 顯示網站名稱而不是「Laravel」。
- [ ] 若有開維護模式：前台任一頁（如 `/products`）顯示維護畫面，`/admin` 仍可進入。

## 回復方式

- 程式碼：回到上一個 commit 重新部署。
- 資料庫：`php artisan migrate:rollback --step=1` 會把兩個金鑰欄位解密並改回 `varchar`（同樣需要正確的 `APP_KEY`）；有疑慮時直接還原備份。
